# Перевод Bookmarks

[🇬🇧 English](../../.github/TRANSLATING.md) | **🇷🇺 Русский** | [🇪🇸 Español](../es/TRANSLATING.md) | [🇧🇷 Português (Brasil)](../pt-BR/TRANSLATING.md) | [🇫🇷 Français](../fr/TRANSLATING.md) | [🇩🇪 Deutsch](../de/TRANSLATING.md) | [🇨🇳 中文（简体）](../zh-CN/TRANSLATING.md) | [🇯🇵 日本語](../ja/TRANSLATING.md) | [🇮🇳 हिन्दी](../hi/TRANSLATING.md) | [🇸🇦 العربية](../ar/TRANSLATING.md)

Тексты интерфейса лежат в `_locales/<code>/messages.json` (стандартный формат Chrome `chrome.i18n`).
Это руководство — только об этом файле. Chrome выбирает папку, которая совпадает с языком браузера;
если такой папки нет, используется английский текст (`_locales/en`).

## Добавить новый язык

1. Выберите код из [списка локалей Chrome](https://developer.chrome.com/docs/extensions/reference/api/i18n#locales).
   Chrome игнорирует коды, которые не поддерживает. В имени папки используйте нижнее подчёркивание: `pt_BR`, `zh_CN`, `es_419`.
2. Скопируйте `_locales/en/messages.json` в `_locales/<code>/messages.json`.
3. Укажите в `locale` тот же код, но с дефисом: `pt-BR`, `zh-CN`, `es-419`.
4. Укажите в `dir` значение `ltr` или `rtl`.
5. Переведите каждое `message`, затем выполните проверки ниже.

Менять код не нужно: тесты сами находят все папки в `_locales/`.

## Ключи и поля

- **Никогда не меняйте ключ** (имя перед `"message"`). Код обращается к сообщениям по этим именам.
- **`message`** — текст, который вы переводите.
- **`description`** — подсказка переводчику, например где появляется текст. В расширении не показывается.
  В `en` каждому сообщению с `placeholders` нужно описание, включая каждую форму множественного числа (`_one`, `_other`…): укажите, где показывается текст и что такое каждый `$NAME$`.
  Это проверяет `npm test`. В других языках описание можно не писать.
- **`locale`** — код языка файла. От него зависят формы множественного числа и `lang` страницы.
- **`dir`** — `ltr` (слева направо) или `rtl` (справа налево, например арабский, иврит, персидский, урду).
  Страницы берут направление отсюда.

## Подстановки

`$NAME$` в `message` заменяется значением подстановки с этим именем.
Сохраните имя и знаки `$`, а саму подстановку поставьте туда, где она нужна в вашем языке:

```json
"more_results": {
  "message": "$COUNT$ more — refine the search",
  "placeholders": {
    "count": { "content": "$1" }
  }
}
```

- Используйте те же имена подстановок, что и в `en`. `content` остаётся `$1`, `$2`… как в `en`.
- Не переводите текст внутри `$…$`.
- Чтобы получить знак доллара, пишите `$$`.

## Формы множественного числа

У сообщения с числом на каждую категорию множественного числа CLDR свой ключ: `<key>_one`, `<key>_few`, `<key>_many`, `<key>_other`.
Берите категории вашего языка и все: их перечисляют [правила множественного числа CLDR](https://www.unicode.org/cldr/charts/latest/supplemental/language_plural_rules.html)
(в английском `one` и `other`; в русском `one`, `few`, `many`, `other`).
`npm test` падает, если какой-то категории нет, и называет недостающие ключи. `_other` обязательна.
Не оставляйте рядом с формами простой ключ (`bookmarks`).

```json
"bookmarks_one": {
  "message": "$COUNT$ bookmark",
  "placeholders": { "count": { "content": "$1" } }
},
"bookmarks_other": {
  "message": "$COUNT$ bookmarks",
  "placeholders": { "count": { "content": "$1" } }
}
```

Русский (`ru`) для того же ключа использует `bookmarks_one` («$COUNT$ закладка»), `_few` («$COUNT$ закладки»),
`_many` («$COUNT$ закладок»), `_other` («$COUNT$ закладки»).

## Слова для палитры команд (`cmd_*_words`)

У каждой команды есть `cmd_<id>` (название), при необходимости `cmd_<id>_note` (вторая строка) и `cmd_<id>_words`:
дополнительные слова для поиска в палитре на вашем языке, через пробел.
Английские слова для поиска работают всегда, поэтому `cmd_*_words` в `en` пустые.
Ключи с пустыми значениями допустимы, но существовать должны все.

```json
"cmd_search_words": {
  "message": "найти фильтр",
  "description": "Extra words to find the command in the palette, in your language; the English words always work"
}
```

## Проверка локально

Нужен Node.js 20.19+, 22.13+ или 24+ (в CI — 22).

```sh
npm ci            # install dependencies
npm test          # checks every language in _locales/
npm run lint
npm run package   # builds dist/*.zip; _locales/ is included
```

`npm test` проверяет для каждого языка:

- те же ключи, что в `en` (ни пропущенных, ни лишних; формы множественного числа считаются одним ключом);
- `locale` и `dir` заданы, а `locale` совпадает с именем папки;
- формы множественного числа: есть каждая категория языка, лишних нет, `_other` на месте;
- подстановки совпадают с `en`, а каждый `content` — от `$1` до `$9`;
- в `en` у каждого сообщения с подстановками есть `description`;
- каждый ключ, который использует код, есть в `en`.

Чтобы увидеть интерфейс на своём языке, загрузите распакованное расширение в браузере с этим языком:

1. Установите язык интерфейса браузера (Chrome: Настройки → Языки; перезапустите браузер).
2. Откройте `chrome://extensions`, включите «Режим разработчика» («Developer mode»), нажмите «Загрузить распакованное» («Load unpacked») и выберите корень репозитория.
3. Откройте боковую панель и проверьте тексты, формы множественного числа и, для `rtl`, раскладку.

`npm run test:browser` (нужен `npx playwright install chromium`) открывает страницы справки, настроек и боковой панели в настоящем браузере:
по разу для каждой папки языка в `_locales/`, для иврита (перевода нет, поэтому английский текст) и для вымышленного иврита справа налево.
Пока работаете, проверяйте только свой язык: `SMOKE_LOCALES=pt_BR npm run test:browser` (имена через запятую: имена папок, `he`, `he-rtl`).

## Обновить существующий перевод

Когда в `en` появляются новые ключи или он меняется, `npm test` падает и перечисляет ключи, которых не хватает в каждом языке.
Добавьте их, переведите и снова запустите `npm test`. Удалите ключи, которых в `en` больше нет.

## Открыть pull request

1. Создайте ветку от `dev`, закоммитьте `_locales/<code>/messages.json`.
2. Выполните проверки выше.
3. Откройте pull request в `dev` (`gh pr create --base dev` или на GitHub).
   В описании укажите, какой язык и новый ли он или это исправление.
   Вопросы и проблемы: откройте issue с формой **Translation**.
