# Bookmarks का अनुवाद

[🇬🇧 English](../../.github/TRANSLATING.md) | [🇷🇺 Русский](../ru/TRANSLATING.md) | [🇪🇸 Español](../es/TRANSLATING.md) | [🇧🇷 Português (Brasil)](../pt-BR/TRANSLATING.md) | [🇫🇷 Français](../fr/TRANSLATING.md) | [🇩🇪 Deutsch](../de/TRANSLATING.md) | [🇨🇳 中文（简体）](../zh-CN/TRANSLATING.md) | [🇯🇵 日本語](../ja/TRANSLATING.md) | **🇮🇳 हिन्दी** | [🇸🇦 العربية](../ar/TRANSLATING.md)

इंटरफ़ेस का टेक्स्ट `_locales/<code>/messages.json` में रहता है (Chrome का मानक `chrome.i18n` प्रारूप)।
यह गाइड केवल इसी फ़ाइल के बारे में है। Chrome वह फ़ोल्डर चुनता है जो ब्राउज़र की भाषा से मेल खाता हो;
यदि कोई नहीं है, तो अंग्रेज़ी टेक्स्ट (`_locales/en`) इस्तेमाल होता है।

## नई भाषा जोड़ें

1. [Chrome की लोकेल सूची](https://developer.chrome.com/docs/extensions/reference/api/i18n#locales) से एक कोड चुनें।
   Chrome उन कोड को अनदेखा करता है जिन्हें वह समर्थन नहीं देता। फ़ोल्डर के नाम में अंडरस्कोर इस्तेमाल करें: `pt_BR`, `zh_CN`, `es_419`।
2. `_locales/en/messages.json` को `_locales/<code>/messages.json` में कॉपी करें।
3. `locale` में वही कोड हाइफ़न के साथ रखें: `pt-BR`, `zh-CN`, `es-419`।
4. `dir` को `ltr` या `rtl` पर सेट करें।
5. हर `message` का अनुवाद करें, फिर नीचे दी गई जाँचें चलाएँ।

कोड में बदलाव की ज़रूरत नहीं है: टेस्ट `_locales/` के सभी फ़ोल्डर अपने आप ढूँढ लेते हैं।

## कुंजियाँ और फ़ील्ड

- **कभी कुंजी न बदलें** (`"message"` से पहले का नाम)। कोड इन्हीं नामों का उपयोग करता है।
- **`message`** — वह टेक्स्ट जिसका आप अनुवाद करते हैं।
- **`description`** — अनुवादकों के लिए संदर्भ, जैसे टेक्स्ट कहाँ दिखता है। यह एक्सटेंशन में नहीं दिखता।
  `en` में `placeholders` वाले हर संदेश के लिए एक ज़रूरी है, हर बहुवचन रूप (`_one`, `_other`…) सहित: बताएँ कि टेक्स्ट कहाँ दिखता है और हर `$NAME$` क्या है।
  `npm test` इसकी जाँच करता है। अन्य भाषाएँ इसे छोड़ सकती हैं।
- **`locale`** — फ़ाइल का भाषा कोड। बहुवचन रूप और पेज का `lang` इसी से आते हैं।
- **`dir`** — `ltr` (बाएँ से दाएँ) या `rtl` (दाएँ से बाएँ, जैसे अरबी, हिब्रू, फ़ारसी, उर्दू)।
  पेज अपनी दिशा इसी से लेते हैं।

## प्लेसहोल्डर

`message` में `$NAME$` को उसी नाम वाले प्लेसहोल्डर के मान से बदल दिया जाता है।
नाम और `$` चिह्न वैसे ही रखें, और प्लेसहोल्डर को वहाँ ले जाएँ जहाँ आपकी भाषा को उसकी ज़रूरत हो:

```json
"more_results": {
  "message": "$COUNT$ more — refine the search",
  "placeholders": {
    "count": { "content": "$1" }
  }
}
```

- `en` जैसे ही प्लेसहोल्डर नाम इस्तेमाल करें। `content` `en` की तरह `$1`, `$2`… ही रहता है।
- `$…$` के अंदर का टेक्स्ट अनुवाद न करें।
- शाब्दिक डॉलर चिह्न के लिए `$$` लिखें।

## बहुवचन रूप

संख्या वाले संदेश में हर CLDR बहुवचन श्रेणी के लिए एक कुंजी होती है: `<key>_one`, `<key>_few`, `<key>_many`, `<key>_other`।
अपनी भाषा की श्रेणियाँ इस्तेमाल करें, और सभी: [CLDR बहुवचन नियम](https://www.unicode.org/cldr/charts/latest/supplemental/language_plural_rules.html)
उन्हें सूचीबद्ध करते हैं (अंग्रेज़ी में `one` और `other` हैं; रूसी में `one`, `few`, `many`, `other`)।
कोई श्रेणी छूटने पर `npm test` विफल होता है और छूटी हुई कुंजियों के नाम बताता है। `_other` ज़रूरी है।
इन रूपों के साथ सादी कुंजी (`bookmarks`) न रखें।

```json
"bookmarks_one": {
  "message": "$COUNT$ bookmark",
  "placeholders": { "count": { "content": "$1" } }
},
"bookmarks_other": {
  "message": "$COUNT$ bookmarks",
  "placeholders": { "count": { "content": "$1" } }
}
```

उसी कुंजी के लिए रूसी (`ru`) `bookmarks_one` ("$COUNT$ закладка"), `_few` ("$COUNT$ закладки"),
`_many` ("$COUNT$ закладок"), `_other` ("$COUNT$ закладки") इस्तेमाल करती है।

## कमांड पैलेट के शब्द (`cmd_*_words`)

हर कमांड में `cmd_<id>` (उसका नाम), वैकल्पिक रूप से `cmd_<id>_note` (दूसरी पंक्ति) और `cmd_<id>_words` होता है:
पैलेट में खोजने के लिए आपकी भाषा के अतिरिक्त शब्द, स्पेस से अलग किए हुए।
अंग्रेज़ी खोज शब्द हमेशा भी इस्तेमाल होते हैं, इसलिए `en` में `cmd_*_words` खाली रहते हैं।
खाली मान वाली कुंजियाँ मान्य हैं, पर सभी मौजूद होनी चाहिए।

```json
"cmd_search_words": {
  "message": "найти фильтр",
  "description": "Extra words to find the command in the palette, in your language; the English words always work"
}
```

## स्थानीय रूप से जाँचें

Node.js 20.19+, 22.13+ या 24+ चाहिए (CI 22 इस्तेमाल करता है)।

```sh
npm ci            # install dependencies
npm test          # checks every language in _locales/
npm run lint
npm run package   # builds dist/*.zip; _locales/ is included
```

`npm test` हर भाषा के लिए जाँचता है:

- `en` जैसी ही कुंजियाँ (कोई छूटी या अतिरिक्त नहीं; बहुवचन रूप एक कुंजी गिने जाते हैं);
- `locale` और `dir` सेट हैं, और `locale` फ़ोल्डर के नाम से मेल खाता है;
- बहुवचन रूप: भाषा की हर श्रेणी मौजूद है, कोई और नहीं, और `_other` मौजूद है;
- प्लेसहोल्डर `en` से मेल खाते हैं, और हर `content` `$1`…`$9` है;
- `en` में प्लेसहोल्डर वाले हर संदेश का `description` है;
- कोड जो भी कुंजी इस्तेमाल करता है वह `en` में मौजूद है।

अपनी भाषा में इंटरफ़ेस देखने के लिए, उस भाषा वाले ब्राउज़र में अनपैक्ड एक्सटेंशन लोड करें:

1. ब्राउज़र की इंटरफ़ेस भाषा अपनी भाषा पर सेट करें (Chrome: सेटिंग → भाषाएँ; ब्राउज़र रीस्टार्ट करें)।
2. `chrome://extensions` खोलें, "डेवलपर मोड" ("Developer mode") चालू करें, "अनपैक्ड लोड करें" ("Load unpacked") पर क्लिक करें और रिपॉज़िटरी का रूट चुनें।
3. साइड पैनल खोलें और टेक्स्ट, बहुवचन रूप और, `rtl` के लिए, लेआउट जाँचें।

`npm run test:browser` (`npx playwright install chromium` ज़रूरी) असली ब्राउज़र में सहायता, विकल्प और साइड पैनल पेज खोलता है,
`_locales/` के हर भाषा फ़ोल्डर के लिए एक बार, हिब्रू (कोई अनुवाद नहीं, इसलिए अंग्रेज़ी टेक्स्ट) के लिए एक बार, और नकली दाएँ-से-बाएँ हिब्रू के लिए एक बार।
काम करते समय केवल अपनी भाषा जाँचें: `SMOKE_LOCALES=pt_BR npm run test:browser` (नाम कॉमा से अलग: फ़ोल्डर के नाम, `he`, `he-rtl`)।

## मौजूदा अनुवाद अपडेट करें

जब `en` में नई कुंजियाँ आती हैं या वह बदलता है, तो `npm test` विफल होता है और हर भाषा में छूटी कुंजियों की सूची देता है।
उन्हें जोड़ें, अनुवाद करें और फिर `npm test` चलाएँ। जो कुंजियाँ अब `en` में नहीं हैं उन्हें हटा दें।

## पुल रिक्वेस्ट खोलें

1. `dev` से ब्रांच बनाएँ, `_locales/<code>/messages.json` कमिट करें।
2. ऊपर की जाँचें चलाएँ।
3. `dev` में पुल रिक्वेस्ट खोलें (`gh pr create --base dev`, या GitHub पर)।
   विवरण में बताएँ कि कौन-सी भाषा है और वह नई है या सुधार।
   प्रश्न और समस्याएँ: **Translation** फ़ॉर्म से issue खोलें।
