# Участие в разработке

[🇬🇧 English](CONTRIBUTING.md) | **🇷🇺 Русский**

Расширение — чистый JavaScript (Manifest V3) без сборки: файлы из корня репозитория
браузер загружает как есть. Страницы (`panel.html`, `options.html`, `help.html`) подключают
ES-модули (`<script type="module">`) с явными импортами; общее для них — в `commands.js`.
Фоновый скрипт `background.js` — обычный service worker, не модуль. Код панели — в `panel/`
по модулям; запуск и порядок подписки на события — в `panel/main.js`, общее изменяемое
состояние — в `panel/state.js`. Тексты интерфейса — в `_locales/<язык>/messages.json`
(стандартный `chrome.i18n`), их показывает `i18n.js` (`t`, множественное число, направление
страницы). Инструменты разработки (`package.json`, `eslint.config.js`, `test/`, `scripts/`)
в релиз не попадают.

### Модули панели

Модули `panel/` импортируют друг друга только сверху вниз, циклов нет — это проверяет
`test/panel-imports.test.js` (при цикле печатает его путь). Слои, от нижнего к верхнему:

1. без зависимостей от панели: `util`, `dom`, `url`, `search`, `place` (куда встаёт перенос), затем `state`, `nodes`, `history`
   (история правок для отмены и повтора: все изменения закладок из панели идут через её `begin()`);
2. `ui` (окно подтверждения, сообщения, фокус), `keymap` (подсказки клавиш), `tree` (чтение
   дерева, кэш узлов);
3. `search-index` (индекс поиска), `tabs`, `marks`;
4. `render`, затем `find` (вход в поиск и выход), `open`, `edit`, `palette` (выбор из списка);
5. `move-to`, `link`, `search-input`;
6. `actions` (что делает каждая команда);
7. `keys`, `mouse`, `drag` (перетаскивание мышью), затем `main`.

Модуль импортирует только из слоёв ниже. Если нижнему модулю нужно позвать верхний, он
не импортирует его, а получает вызов снаружи: `tree` зовёт `onTreeApplied(callback)` после
каждого прочтения дерева (перерисовку задаёт `main.js`), `openPalette(run)` выполняет выбранную
команду через переданную `run`. Состояние, которое нужно нескольким слоям, лежит в `state`
(например, `state.pending` — начатая последовательность клавиш: её ведёт `keys`, а отменяет
и `palette`). Шины событий нет: обратный вызов задаётся явно, в одном месте, при запуске.
Порядок подписок на события задаёт `main.js` и важен, где на одно событие подписано несколько
обработчиков.

## Разработка

Нужен Node.js 20.19+, 22.13+ или 24+ (требование ESLint 10).

```sh
npm ci            # установка зависимостей
npm run lint      # ESLint
npm test          # тесты (node --test)
npm run package   # сборка dist/airnook-bookmarks-<версия>.zip и проверка архива
npm run test:browser  # смоук-тест в Chromium (нужен npx playwright install chromium)
```

Запуск расширения: `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное»
→ корень репозитория.

### Линтер

Страницы — ES-модули: всё, что файл берёт из другого (`COMMANDS`, `chordOf` из
`commands.js` и т.п.), он импортирует явно, иначе линтер укажет на неизвестное имя.
Пустой `catch {}` линтер не пропускает: напишите внутри, почему ошибку можно игнорировать.

### Тесты

Модули без DOM (`commands.js`, чистые функции панели в `panel/`) тесты импортируют
напрямую. `background.js` — не модуль, поэтому тесты грузят его через `node:vm` со стабом
`chrome` (см. `test/load.js`); страницу настроек — тоже через `node:vm` со стабами DOM
(см. `test/options-page.js`).

`npm run test:browser` собирает архив, загружает расширение в Chromium от Playwright
и проверяет страницы и основные клавиши панели: прогон на каждом языке из `_locales/`,
плюс иврит без перевода и фиктивный иврит справа налево. Только нужные языки:
`SMOKE_LOCALES=ru,en npm run test:browser` (имена каталогов `_locales`, `he`, `he-rtl`).
В `npm test` и CI он не входит: браузера там может не быть.

### Сборка

Состав архива — замыкание ссылок: `manifest.json` → всё, на что он ссылается
(service worker, страницы, иконки) → для каждой html-страницы её `<script src>`,
`<link href>` и `<img src>`, для каждого скрипта — его статические `import` и `export … from`
→ рекурсивно. Плюс каталог `_locales/`, если он есть, и
страницы из `EXTRA_PAGES` в `scripts/package.mjs`: их код открывает по имени
(например, `help.html`), поэтому по ссылкам их не найти. Всё остальное, включая любые
новые служебные файлы в корне, в архив не попадает.

Если в `.js` расширения появилась ссылка на новую html-страницу, которой нет в архиве,
сборка упадёт с подсказкой добавить её в `EXTRA_PAGES`. После сборки отдельная проверка
убеждается, что в архиве нет `package.json`, конфигов линтера, `test/`, `scripts/`,
`.github/`, `README*.md`, `docs/` (картинки README), `LICENSE`, `TODO.md`, `CONTRIBUTING*.md`, скрытых файлов и что все ссылки
на месте; при ошибке команда завершается с ненулевым кодом.

CI (`.github/workflows/ci.yml`) выполняет то же самое на каждый push и pull request
в `dev` и `main`.

## Переводы

Перевод интерфейса — в `_locales/<язык>/messages.json`. Как добавить язык или поправить
перевод, и что проверяет `npm test`, — в [TRANSLATING.md](TRANSLATING.md) (на английском).
Новый каталог в `_locales/` подхватывается сам, менять код не нужно.

## Как выпустить релиз

1. Поднимите `version` в `manifest.json` и слейте изменение в `main`.
2. Создайте на `main` тег `vX.Y.Z`, где `X.Y.Z` — ровно версия из `manifest.json`:

   ```sh
   git checkout main && git pull
   git tag vX.Y.Z
   git push origin vX.Y.Z
   ```

3. Workflow `release.yml` проверит, что тег совпадает с версией, прогонит lint и тесты,
   соберёт архив и опубликует GitHub Release с `airnook-bookmarks-X.Y.Z.zip`.

Если тег и версия не совпали, workflow упадёт до сборки: удалите тег
(`git push --delete origin vX.Y.Z`), поправьте версию и повторите.
